# 🚦 دليل المشروع الهندسي الشامل للتسليم والعرض في المعرض
## نظام إدارة المرور التكيفي الذكي (IoT Smart Adaptive Traffic System)

> **ملاحظة للمهندس المستلم:** هذا الملف يحتوي على كل صغيرة وكبيرة في المشروع؛ التصميم الهندسي، الأبعاد الفيزيائية للمجسم، جداول المنافذ، وشرح الكود البرمجي تفصيلياً سطراً بسطر لتمكينك من فهمه وعرضه ومناقشته أمام لجنة التحكيم بكل ثقة واحترافية.

---

## 🏛️ 1. المخطط المعماري العام للمشروع (System Architecture)

يعتمد المشروع معمارية إنترنت الأشياء الصناعية (Industrial IoT Architecture) خماسية الطبقات:

```
[مجسم التقاطع الفيزيائي (12 ليد + 8 حساسات كثافة + 1 حساس إسعاف)]
                               │
                       (GPIO Wire Bus)
                               ▼
            [متحكم ESP32 - العقل التكيفي الميداني]
                               │
             (WiFi / MQTT Protocol - Port 1883)
                               ▼
        [وسيط Mosquitto MQTT المحلي (Local Broker)]
                               │
            (WebSocket / MQTT Internal Engine)
                               ▼
        [خادم Node-RED المركزي (Backend Engine)]
         ├── لوحة المراقبة الحية (Dashboard 2.0)
         ├── واجهة برمجية RESTful API (GET /status & POST /emergency)
         └── تنبيهات الإيميل وتليجرام (Alerts System)
                               │
             (HTTP REST API over WiFi - Port 1880)
                               ▼
     [تطبيق الهاتف المحمول الذكي (Flutter Mobile App)]
```

## 📐 2. الأبعاد الهندسية والتصميم الفيزيائي للمجسم (Physical Diorama Specs)

لكي يظهر المجسم كنموذج هندسي واقعي (Realistic Diorama) متقن:

### أ) أبعاد قاعدة المجسم والطرق:
* **حجم لوح القاعدة (Base Board):** يُفضل لوح فوم مقوى (Foam Board) أو خشب MDF بمقاس **`80 cm × 80 cm`** (أو `100 cm × 100 cm`).
* **عرض الشارع (Road Width):** **`14 cm`** لكل ذراع من أذرع التقاطع الأربعة:
  * **مسار الدخول (Incoming Lane):** بعرض **`7 cm`** (عليه خط التوقف وحساسات الكثافة وإشارة المرور).
  * **مسار الخروج (Outgoing Lane):** بعرض **`7 cm`** (للسيارات المغادرة، مفتوح دائماً ولا توجد عليه إشارات وفق معايير هندسة المرور ITS).
* **طول كل ذراع:** **`33 cm`** من حافة التقاطع إلى طرف اللوح.

### ب) مواقع الحساسات ومسافاتها (Sensor Locations):
1. **حساس خط التوقف (Stop-Line Sensor):**
   * يوضع على بعد **`3 cm إلى 5 cm`** خلف خط التوقف الأبيض مباشرة.
   * وظيفته: كشف وصول أول سيارة عند الإشارة وقياس زمن توقفها (Occupancy Dwell Time).
2. **حساس نهاية المسار (Queue-Tail Sensor):**
   * يوضع على بعد **`18 cm إلى 22 cm`** خلف خط التوقف (نهاية الذراع).
   * وظيفته: كشف امتداد طابور السيارات (Spillback Queue / Congestion).
3. **حساس الإسعاف الفعلي (FR/IR Sensor - منفذ GPIO 23):**
   * يوضع في **مسار الشمال (Lane 1)** على بعد **`25 cm إلى 30 cm`** موجهاً للأمام لاستقبال إشارة سيارة الإسعاف المقتربة قبل وصولها للتقاطع.
4. **أعمدة إشارات المرور (Traffic Light Poles):**
   * ارتفاع العمود: **`12 cm إلى 15 cm`** مصنوع من أنبوب بلاستيكي رفيع أو طباعة 3D.
   * ترتيب الألوان من الأعلى للأسفل: **أحمر (Red) $\rightarrow$ أصفر (Yellow) $\rightarrow$ أخضر (Green)**.

## 🔌 3. جدول توزيع منافذ الـ ESP32 المعتمد (Master Pinout)

> **إجمالي المنافذ المستخدمة: 21 منفذاً فقط** (محسوبة بعناية لتجنب منافذ الفلاش 6-11، ومنفذ الإقلاع الحساس GPIO 0، ومنافذ السيريال 1 و 3).

| العنصر | الاتجاه / المسار | رقم المنفذ (GPIO) | نوع المنفذ في الكود | ملاحظة كهربائية وهندسية |
| :--- | :--- | :--- | :--- | :--- |
| **إشارات الشمال (North)** | Lane 0 (Index 0) | أحمر: `13`، أصفر: `12`، أخضر: `14` | OUTPUT | مخارج رقمية مباشرة إلى مقاومات 220Ω |
| **إشارات الشرق (East)** | Lane 1 (Index 1) | أحمر: `26`، أصفر: `25`، أخضر: `33` | OUTPUT | مخارج رقمية مباشرة إلى مقاومات 220Ω |
| **إشارات الجنوب (South)** | Lane 2 (Index 2) | أحمر: `15`، أصفر: `2`، أخضر: `4` | OUTPUT | مخارج رقمية مباشرة إلى مقاومات 220Ω |
| **إشارات الغرب (West)** | Lane 3 (Index 3) | أحمر: `18`، أصفر: `19`، أخضر: `21` | OUTPUT | مخارج رقمية مباشرة إلى مقاومات 220Ω |
| **حساسات كثافة الشمال** | Lane 0 (North) | التوقف: `27` ، نهاية المسار: `32` | INPUT_PULLUP | مفعل السحب الداخلي |
| **حساسات كثافة الشرق** | Lane 1 (East) | التوقف: `34` ، نهاية المسار: `35` | INPUT | **Input Only** (لا تسحب داخلياً؛ تتطلب مخرج حساس رقمي) |
| **حساسات كثافة الجنوب** | Lane 2 (South) | التوقف: `36` ، نهاية المسار: `39` | INPUT | **Input Only** (لا تسحب داخلياً؛ تتطلب مخرج حساس رقمي) |
| **حساسات كثافة الغرب** | Lane 3 (West) | التوقف: `5` ، نهاية المسار: `22` | INPUT_PULLUP | مفعل السحب الداخلي |
| **حساس الإسعاف المادي** | مسار الشمال (Lane 1) | **`23`** | INPUT_PULLUP | **حساس FR/IR مادي واحد مستقر وآمن 100%** |

## 🧠 4. شرح كود الـ ESP32 بالتفصيل المعمق (`esp32_traffic_system.ino`)

الكود مكتوب بلغة C++ لبيئة Arduino، ويعتمد على معمارية **آلة الحالات غير المعطلة (Non-Blocking Finite State Machine - FSM)** باستخدام `millis()` بدلاً من `delay()`.

### أ) مصفوفة حالات الإشارات (States 0 to 7):
يمر التقاطع بـ 8 حالات دورية (كل مسار له حالتان: أخضر ثم أصفر):
* **State 0:** مسار الشمال أخضر (North Green) - باقي المسارات أحمر.
* **State 1:** مسار الشمال أصفر (North Yellow) - تمهيد للإغلاق.
* **State 2:** مسار الشرق أخضر (East Green).
* **State 3:** مسار الشرق أصفر (East Yellow).
* **State 4:** مسار الجنوب أخضر (South Green).
* **State 5:** مسار الجنوب أصفر (South Yellow).
* **State 6:** مسار الغرب أخضر (West Green).
* **State 7:** مسار الغرب أصفر (West Yellow).

> **العملية الحسابية الذكية:** 
> - رقم المسار الفعال = `currentState / 2`
> - هل الإشارة صفراء؟ = `(currentState % 2 != 0)`

---

### ب) خوارزمية قياس الكثافة عبر زمن الإشغال (`updateDensities()`):
بدلاً من عد النبضات الفردية المعرضة للخطأ، تقرأ الدالة الحساسين وتحدد 4 مستويات:
```cpp
void updateDensities() {
  unsigned long now = millis();
  for (int i = 0; i < 4; i++) {
    bool stopActive = (digitalRead(DENSITY_PINS[i][0]) == LOW);
    bool tailActive = (digitalRead(DENSITY_PINS[i][1]) == LOW);

    if (stopActive) {
      if (stopDetectTime[i] == 0) stopDetectTime[i] = now;
    } else {
      stopDetectTime[i] = 0;
    }

    if (tailActive) {
      laneDensity[i] = HIGH_DENSITY;   // طابور ممتلئ
      allocatedGreenTime[i] = 25000;    // 25 ثانية
    } 
    else if (stopActive && (now - stopDetectTime[i] >= 2000)) {
      laneDensity[i] = MEDIUM_DENSITY; // سيارات متوقفة > 2 ثانية
      allocatedGreenTime[i] = 15000;    // 15 ثانية
    } 
    else if (stopActive) {
      laneDensity[i] = LOW_DENSITY;    // وصول سيارة حديثة
      allocatedGreenTime[i] = 8000;     // 8 ثوانٍ
    } 
    else {
      laneDensity[i] = EMPTY;          // المسار فارغ
      allocatedGreenTime[i] = 3000;     // 3 ثوانٍ (تخطي سريع)
    }
  }
}
```

---

### ج) ميزة الإخلاء السريع وتوفير الوقت (Gap-Out Logic):
أثناء عمل الإشارة الخضراء لأي شارع:
- يمنح الشارع مهلة دنيا **4 ثوانٍ** لمرور السيارات الأولى.
- إذا فرغ الشارع تماماً قبل انتهاء الوقت المخصص (`laneDensity == EMPTY`)، يقطع الكود الإشارة الخضراء فوراً وينتقل للأصفر!
- **الأثر الهندسي:** يمنع بقاء الإشارة خضراء لشارع فارغ بينما الشوارع الأخرى تنتظر.

---

### د) خوارزمية إخلاء الطوارئ لسيارات الإسعاف (`triggerEmergency()`):
1. **الاستشعار:** يتم إما بحساس الـ FR المادي (`GPIO 23`) أو بأمر لاسلكي عبر الـ MQTT (تطبيق الموبايل أو الداشبورد).
2. **الاستجابة:**
   - يحفظ الكود الحالة الحالية للتقاطع `interruptedState`.
   - إذا كان الشارع المطلوب مفتوحاً بالفعل، يمدد له الأخضر لـ **10 ثوانٍ**.
   - إذا كان شارعاً آخر مفتوحاً، يحوله فوراً إلى أصفر (Clearance Yellow لمدة ثانيتين) لحماية المركبات من التصادم، ثم يفتح الأخضر لمسار الإسعاف.
   - بعد انتهاء الـ 10 ثوانٍ، يعود النظام بسلاسة للنقطة التي توقف عندها في الدورة الطبيعية دون أن يضيع دور أي مسار.

## 🌐 5. خادم Node-RED وواجهات الـ REST API

يستمع الخادم إلى الـ MQTT وينظم البيانات لجميع الأطراف:
1. **واجهة القراءة (`GET /status`):**
   - تعيد كائن JSON كامل بحالة التقاطع:
   ```json
   {
     "north": { "status": "GREEN", "cars": 0, "density": "EMPTY", "time": 3 },
     "east":  { "status": "RED",   "cars": 2, "density": "MED",   "time": 15 },
     "south": { "status": "RED",   "cars": 3, "density": "HIGH",  "time": 25 },
     "west":  { "status": "RED",   "cars": 1, "density": "LOW",   "time": 8 },
     "activeLane": 0,
     "emergencyLane": 0,
     "isEmergency": false
   }
   ```
2. **واجهة التحكم (`POST /emergency`):**
   - تستقبل `{ "lane": 1 }` وتنشره فورياً على الـ Topic `sanad/traffic/command`.
3. **لوحة Dashboard 2.0:**
   - رابطها: `http://localhost:1880/dashboard`
   - تعرض عدادات رقمية، ألوان الإشارات الحية، وزر طوارئ بنقرة واحدة.

## 📱 6. تطبيق الهاتف الذكي (Flutter App)

- **معمارية الكود:** نظيفة ومبنية على نمط Provider / State Management.
- **خدمة الاتصال (`TrafficApiService`):**
  - تقوم بعمل Polling دوري كل 800ms لنقطة `GET /status`.
  - تعرض رسوم الشوارع الأربعة، عداد الكثافة لكل شارع، ومؤشر الإشارة النشطة بالألوان الحقيقية.
- **زر تعديل الـ IP المدمج:** في شريط العنوان (AppBar) يوجد زر ترس يتيح كتابة IP اللابتوب مباشرة دون إعادة تجميع التطبيق.
